## 本轮功能结果

### R1.2 组合回归修订

修复起点：公开源码 `ff622c66443a510b4daac4449ac7965be7cc00bf`，本地 `fix/r1-hook-composition` 分支。
本次同步修复代码与验收边界文档；运行包不变，未发布 Mod Release。没有修改 UI、金钱结算或 Framework 业务。

- F1：三个引擎按 CE 自有代理的底层身份解析父路径，父 Deep 不再令子 Var/Raw 失活。仅透明内部登记的代理，第三方 Proxy 保留自身身份与陷阱。
- F2：根安装剥离旧 CE 包装；嵌套访问保留其他注册的代理，并复用当前 binding 自己的代理。根代理只要仍在对应 CE 包装链中就保持身份，避免子对象自回写使有效子规则失活。父子双方变换时，祖先先执行，再将结果传给后代；各执行一次。两种登记顺序、重复安装、更新、分别注销及替换后的失活与重绑均有定向断言。
- 新增 `tests/hooks-composition.test.mjs` 六项：四项原始组合回归及必要生命周期边界、代理回写避免重复变换、保留第三方 Proxy 陷阱。四项原始回归已在未修复 R1.1 上观察到预期失败；自有代理回写测试也在修复过程捕获了重复变换。
- F3：负责人确认“保留显式登记顺序，自动恢复不提高优先级”。活动执行表与文档内顺序记录分离，恢复 S 不再把它提升到 T 之后。顺序记录仅含身份字符串、显式标记和序号，没有 State、目标对象或 transform 闭包。
- 同一规则以引擎内的路径、owner 和定义字段快照识别。快照包含 type/path/targetPath/mode/value/customCode/正负倍率/maxDepth，不含 enabled、State 或对象引用。不同存档复制的同 ID、不同定义各有序位；相同 ID 与定义视为同一逻辑规则。自动恢复不继承其他定义的显式序位。
- 首次遇到的保存定义按列表顺序建立初始序位，低于同文档内的显式登记；已知定义恢复沿用序位。显式新增、更新、重新启用或删除后重建均推进序位。自动禁用/缺失时只移出执行表；删除也不会保留可执行规则，轻量顺序记录保留至文档重启。重启后不持久化会话顺序，重新按保存列表建立初始关系。
- 新增 `tests/hooks-order.test.mjs` 六项，覆盖三个引擎的 A→B→A、显式更新、禁用/重新启用、删除同 ID 重建、不同定义复制 ID 及新文档初始化。修复前六项均以行为断言失败，修复后通过。

### Hook 保留边界

- Deep 的 `after(oldValue, finalValue, ctx)` 接收本层输出，不保证是最终落地值。例如父变换 +1、子变换 ×10，输入 2 最终为 30，父 after 的 finalValue 仍为 3；不能直接作为最终结算回执。
- 注册根不变、只替换嵌套 child 时，旧 child 引用仍可能受祖先 Hook 影响。本次没有全面处理该旧边界，不宣称所有旧引用均失活。
- 直接原地修改已保存且已登记规则的 path/type，可能遗留旧位置登记。普通 UI 使用快照保存，尚未确认本修订新增的正常 UI 触发路径；列入后续调查，不为此扩大当前 R1。
