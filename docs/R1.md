## 本轮功能结果

### R1.2 组合回归修订

修复起点：公开源码 `ff622c66443a510b4daac4449ac7965be7cc00bf`，本地 `fix/r1-hook-composition` 分支。
没有推送、合并 main 或发布 Release；没有修改 UI、金钱结算或 Framework 业务。

- F1：三个引擎按 CE 自有代理的底层身份解析父路径，父 Deep 不再令子 Var/Raw 失活。仅透明内部登记的代理，第三方 Proxy 保留自身身份与陷阱。
- F2：根安装剥离旧 CE 包装；嵌套访问保留其他注册的代理，并复用当前 binding 自己的代理。根代理只要仍在对应 CE 包装链中就保持身份，避免子对象自回写使有效子规则失活。父子双方变换时，祖先先执行，再将结果传给后代；各执行一次。两种登记顺序、重复安装、更新、分别注销及替换后的失活与重绑均有定向断言。
- 新增 `tests/hooks-composition.test.mjs` 六项：四项原始组合回归及必要生命周期边界、代理回写避免重复变换、保留第三方 Proxy 陷阱。四项原始回归已在未修复 R1.1 上观察到预期失败；自有代理回写测试也在修复过程捕获了重复变换。
- F3 未修复：同一路径保存规则 S、后来显式登记的临时规则 T、切到无 S 的 B、恢复 A 时，S 会被重新插入 Map 尾部并覆盖 T。若采用“自动恢复不推进显式登记顺序”，这是待修缺陷；替代合同也须明确记录。尚未替负责人确定同 ID 跨存档或配置变更的身份语义。

以下为 R1.1 已实现能力与保留边界；不能用单项检查通过覆盖上述 F3 未决问题。

## 构建与验证

Node.js 要求 >=22.12；本次使用 macOS ARM64、Node 24.18.0、npm 11.16.0。
在工程根目录运行：

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run verify
```

`npm run build` 生成 `dist/cheat-extended-r1.mod.zip` 与 `dist/assembly.json`。
`npm test` 使用 Node 内置 test runner；仅 JSZip 是开发依赖，不在游戏里加载。
安装构建依赖需要网络；运行制品未新增网络依赖。

本次完成的关键检查：

- R1.1 历史 `npm run verify`：28/28 通过（24 项 Hook/相邻行为、1 项覆盖 16 场景的可选框架检查、3 项装配检查）；后续新增五项复现全部失败，故此历史结果不构成收口证据。
- R1.2 最终 `npm run verify`：**34/34 通过**，包括原 28 项及六项组合检查；实际 ZIP 仍为 89 个成员、7 个外置 Patch。直接重跑原独立复核五项脚本：F1/F2 四项通过，F3 条件性断言仍失败（实际 10、若保留显式顺序则期望 12，退出码 1）。F3 尚未纳入通过标准，不能用 34 项通过掩盖这一未决问题。
- 六项组合检查可单独执行 `node --test tests/hooks-composition.test.mjs`。只读复查发现的父子 Deep 自回写失活已补断言修复；最终复查未发现剩余重要问题，仍不替代真实宿主验收。
- 固定旧版定向对照：`CE_TEST_BASELINE=1 node --test --test-name-pattern '^DeepProxy|saved A|permission revocation|nested macro' tests/hooks.test.mjs`：8 项目标断言失败、1 项原有行为通过，退出码 1 为预期。不是游戏运行故障统计。
- 原清单的遗漏 Patch 与缺失文件分别被装配器拒绝。现有输入生成 **89 个 ZIP 成员、7 个外置 Patch 文件**；重新读取真实 ZIP，CRC、成员和输入字节对应通过。同输入两次生成字节一致。
- 全部声明 JS 及普通脚本合并结果通过经典脚本解析；4 个 early、21 个 Twee、3 个 CSS 与原顺序保留，普通脚本只在 Hook 工具前增加注册表。
- 原许可证字节、Spectrum 通知与 OpenCC 来源说明保留；本地改动说明见 [R1-NOTICE.md](../R1-NOTICE.md)。
- R1.1 内部审查曾修正禁用转存、失效 binding 保留旧 State、同 State 自动清算改变顺序；未覆盖 F3 的 owner 消失再恢复，不能视为完整修复。
- `git diff --check` 通过。

声明、打包已验证；**Patch 命中与游戏运行未验证**。具体 ZIP SHA-256 以 `dist/assembly.json` 为准。

## 接续顺序与已知边界

1. 先确定并完成 F3：自动恢复是否推进顺序、跨档同 ID/变更/删除重建的身份合同；只保留轻量顺序元数据，不保留可执行旧 State 或闭包。完成离线组合修订后，再在独立测试宿主核实加载、Patch 命中、第一次写入及真实 A→B→A。
2. R03/R04：金钱监控启停/换档基线、队列寿命与失败传播，明确“直接变量变化是否重结算”的业务合同，检查余额和账目，避免只回滚一个数值。
3. R05/R06：Maple/Simple 六类能力矩阵及时间日历/事件/导航语义；可选查询修复不等于功能对等。
4. Hook 后续：跨引擎同路径竞争、Raw/Var 原始 accessor 恢复、特殊对象/只读属性、共享子对象多路径、数值字符串。根未替换而只替换嵌套 child 时，旧 child 代理仍可作用，是原有且本轮未处理的边界。
5. 再按实际耦合迁移 53 项功能；类型化随模块需要推进，保持原作 UI，适度美化排后。

可交付本次局部修订供审查，F3 尚未解决；正式兼容与发布承诺须基于对应真实证据。
